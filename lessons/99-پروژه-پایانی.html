۱

نقشه‌ی کلی پروژه (قبل از شروع)

قبل از اولین گام، کلِ محصولِ نهایی را ببین تا حینِ ساختن مسیرت را گم نکنی. فروشگاهِ ما از این‌جاها تشکیل شده است:

کدنقشه‌ی روت‌ها
روتِ عمومی (مهمان هم می‌بیند)          پنلِ مدیریت (فقط admin)
------------------------------          ------------------------------
GET  /                       → خانه    GET    /admin               → داشبورد
GET  /products               → فهرست   GET    /admin/products       → فهرست
GET  /products/{product}     → نمایش   GET    /admin/products/create → ساخت
GET  /cart                   → سبد     POST   /admin/products        → ذخیره
POST /cart/{product}         → افزودن  PUT    /admin/products/{product} → بروزرسانی
POST /checkout               → سفارش   DELETE /admin/products/{product} → حذف
POST /login, /register      → ورود
POST /logout                → خروج

جدول‌ها

users (با role) — categories — products (با image و category_id) — orders — order_product (pivot با quantity).

مدل‌ها و روابط

Category ← hasMany → Product ← belongsTo به هم؛ Order belongsTo User و belongsToMany Product (pivot).

میان‌افزار و گیت

auth برای سبد/سفارش، check-role:admin برای پنل، و Gate برای مدیریتِ محصول.

💡 از کجا شروع کنم؟

اگر پروژه‌ای که از بخش ۲ تا ۱۵ ساختی سر جای‌اش است، همان را ادامه بده — این ۱۰ گام دقیقاً رویِ همان پیاده می‌شود. اگر پروژه‌ات را گم کرده‌ای، با composer create-project laravel/laravel shop دوباره بساز و از گام ۱ شروع کن.

۲

گام ۱: اسکلت و قالب x-layout

هدف: تمامِ صفحات یک قالبِ مشترک داشته باشند

در درسِ ۶ قالب را با layouts/app.blade.php و @extends ساختیم. اینجا همان قالب را به شکلِ یک کامپوننتِ Blade می‌نویسیم تا همه‌ی صفحه‌ها کوتاه‌تر شوند:

  • کامپوننتِ resources/views/components/layout.blade.php را بساز با @props(['title' => ...]).
  • داخلش: head با سبکِ سراسری، header با ناوبری، {{ $slot }}، footer.
  • فایلِ سبکِ assets/css/style.css را (از دوره) درِ head متصل کن.
  • ناوبریِ header شامل: خانه، محصولات، سبد خرید و (ورود/ثبت‌نام یا نامِ کاربر + خروج).
کداستفاده درِ هر بلیدِ صفحات
<x-layout title="فروشگاه کوچک">
    <h1>به فروشگاه خوش آمدی</h1>
    <p>... محتوای هر صفحه ...</p>
</x-layout>
تستِ گام
صفحه‌ی / و /products را باز کن: هر دو با همین قالبِ یکسان لود شوند و ناوبریِ بالای صفحه درِ هر دو دیده شود.
۳

گام ۲: Auth و نقش admin

هدف: ثبت‌نام/ورود/خروج + یک کاربرِ مدیر

جمعِ درس‌های ۱۰ و ۱۲: فرمِ ثبت‌نام، ورود با Auth::attempt و خروجِ چندمرحله‌ای.

  • ستونِ role (پیش‌فرضِ customer) با migration به جدولِ users اضافه کن.
  • کنترلرها را بساز: php artisan make:controller AuthController و php artisan make:controller DashboardController.
  • در AuthController: createRegister()/store() (با Hash::make)، createLogin()/store() برای ورود، و logout(). بعدِ ورود موفق: session()->regenerate() + redirect()->intended().
  • خروج: Auth::logout() + invalidate() + regenerateToken().
  • روت‌های پنل را از همین الان با middleware(['auth','check-role:admin']) بساز (میان‌افزارِ نقش از درسِ ۱۱).
  • یک کاربرِ admin بساز (از گام ۴ دائمی می‌شود).
کدroutes/web.php
Route::middleware(['auth', 'check-role:admin'])->prefix('admin')
    ->group(function () {
        Route::get('/', [DashboardController::class, 'index'])->name('admin.dashboard');
        // روت‌های مدیریتِ محصولات درِ گام ۵
    });
تستِ گام
بدونِ ورود برو /admin → باید به صفحه‌ی ورود ریدایرکت شوی. با ادمین وارد شو → به داشبورد برسی. (ترتیبِ میان‌افزارها مهم است: اول auth، بعد check-role.)
۴

گام ۳: جداول و مدل‌ها

هدف: خوابِ دیتابیسیِ فروشگاه

جمعِ درس‌های ۷، ۸ و ۹: migration و مدل + روابط.

کدخلاصه‌ی جداول
categories: id | name | timestamps

products:   id | category_id (FK) | name | description | price | image? | timestamps

orders:     id | user_id (FK) | total | timestamps

order_product: order_id | product_id | quantity        // pivot
  • مدل‌ها: Category (hasMany products)، Product (belongsTo category، belongsToMany orders با ->withPivot('quantity'))، Order (belongsTo user، belongsToMany products)، User (hasMany orders).
  • روی Product با #[Fillable('name', 'description', 'price', 'category_id', 'image')] فیلدهای مجاز را مشخص کن.
  • php artisan migrate را اجرا کن.
تستِ گام
درِ Tinker: $c = Category::create(['name' => 'کتاب']); و $c->products()->create([...]) — رابطه‌ی hasMany باید کار کند.
۵

گام ۴: Seed داده‌ی اولیه

هدف: یک فرمان = فروشگاهِ پر

جمعِ درسِ ۱۳: seeder برای دسته‌ها، factory برای محصولات، و ادمینِ همیشگی.

  • CategorySeeder: کتاب، نوشت‌افزار، گجت (داده‌ی کنترل‌شده).
  • ProductFactory: نام/توضیح/قیمت با fake() و category_id => Category::factory().
  • DatabaseSeeder: ترتیبِ $this->call([CategorySeeder::class, ProductSeeder::class]) + کاربرِ admin@shop.test با role admin.
  • اجرا: php artisan migrate:fresh --seed.
تستِ گام
php artisan tinker → Product::count() باید ۴۰ و User::where('role','admin')->count() باید ۱ باشد.
۶

گام ۵: CRUD محصول در پنل

هدف: مدیر بتواند محصول بسازد، ویرایش کند و حذف کند

جمعِ درس‌های ۸ و ۱۲ با مسیرِ /admin/products و محافظتِ کامل.

کدroutes — داخلِ گروهِ admin
// بدونِ ->names() این نام‌ها با روت‌هایِ عمومیِ مرحله‌ی ۷ قفل می‌شوند؛ پس حتماً بده:
Route::resource('products', Admin\ProductController::class)
    ->except(['show'])     // نمایشِ عمومی جدا درِ سایت است
    ->names('admin.products');
  • index: جدولِ محصولات (تصویر، نام، دسته، قیمت) + دکمه‌ی ساخت/ویرایش/حذف.
  • create/store: فرم با validation؛ فیلدِ category از dropdown دسته‌ها.
  • edit/update: ویرایشِ همان فرم؛ عکسِ فعلی را نشان بده.
  • destroy: حذفِ ردیف + حذفِ فایل (گامِ بعد).
  • پیام‌هایِ فلش موفقیت با redirect()->with('success', ...) و نمایش درِ بلید.
تستِ گام
از پنل یک محصول جدید بساز، ویرایش‌اش کن و بعد حذف‌اش کن — هر بار پیامِ فلشِ درست را درِ صفحه ببین.
۷

گام ۶: آپلود تصویر

هدف: هر محصول یک عکسِ واقعی داشته باشد

جمعِ درسِ ۱۴: دیسکِ public، store()، نمایش با asset() و حذف با Storage::disk('public')->delete().

  • php artisan storage:link را اجرا کن (بدونِ آن، عکس‌ها ۴۰۴ می‌خورند).
  • فرم‌های create/edit را با <input type="file" name="image"> و enctype="multipart/form-data" تکمیل کن.
  • درِ store(): $path = $request->file('image')->store('images', 'public') و همان $path را درِ دیتابیس ذخیره کن.
  • درِ update: اگر hasFile('image')، عکسِ قبلی را با Storage::disk('public')->delete($product->image) پاک کن و مسیرِ جدید را بنویس.
  • درِ destroy: قبل از حذفِ ردیف، فایل را هم پاک کن.
  • نمایش درِ صفحاتِ عمومی: <img src="{{ asset('storage/' . $product->image) }}">، و اگر null بود، placeholder.
تستِ گام
یک فایلِ jpg آپلود کن → درِ صفحه‌ی عمومیِ محصول باید دیده شود. محصول را حذف کن → هم ردیفِ دیتابیس و هم فایلِ واقعی باید بروند.
۸

گام ۷: فهرست عمومی + جستجو + صفحه‌بندی

هدف: مشتری درِ فروشگاه بچرخد و پیداش کند

جمعِ درسِ ۱۳: paginate()، links() و جست‌وجوی ساده با متدِ when() روی کوئری.

کدProductController@index
public function index(Request $request): View
{
    $products = Product::query()
        ->with('category')
        ->when($request->search, fn ($q, $s) =>
            $q->where('name', 'like', "%{$s}%"))
        ->paginate(12)
        ->withQueryString();

    return view('products.index', compact('products'));
}
  • روتِ عمومیِ /products را با only(['index','show']) بساز (سطحِ حمله کوچک — درسِ ۱۵).
  • کارتِ محصول: تصویر، نام، دسته، قیمت با number_format($product->price).
  • فرمِ جستجوی GET /products?search=... و حفظِ پارامتر درِ لینک‌هایِ صفحات.
  • زیرِ فهرست: {{ $products->links() }} + کادرِ «نمایش ۱ تا ۱۲ از ۴۰».
تستِ گام
داده‌ی اولیه با seed و factory ساخته شده، پس هر بار که پروژه را از نو می‌سازی، همان محصول‌ها با همان قیمت‌ها سرِ جایشان هستند. این تنها راهِ درستِ داشتنِ یک محیطِ قابلِ اعتماد است.
۹

گام ۸: سبد خرید و سفارش

هدف: مشتری چند محصول جمع کند و سفارش ثبت شود

جمعِ درسِ ۴: سبدِ ساده با Session و ثبتِ سفارشِ بدونِ پرداختِ واقعی. ساخت کنترلر: php artisan make:controller CartController.

کدapp/Http/Controllers/CartController.php
// افزودن به سبد — ذخیره: product_id => quantity
$cart = session()->get('cart', []);
$cart[$product->id] = ($cart[$product->id] ?? 0) + 1;
session()->put('cart', $cart);

// ثبتِ سفارش (فقط لاگین‌کرده)
$order = Order::create(['user_id' => auth()->id(), 'total' => $total]);
foreach ($cart as $pid => $qty) {
    $order->products()->attach($pid, ['quantity' => $qty]);
}
session()->forget('cart');
  • روت‌هایِ سبد: GET /cart، POST /cart/{product}، DELETE /cart/{product}.
  • صفحه‌ی سبد: لیستِ اقلام با قیمتِ واحد، تعداد و جمعِ کل (از داده‌ی واقعیِ دیتابیس، نه کوکی).
  • روتِ POST /checkout با middlewareِ auth؛ اگر مهمان بود → login.
  • جمعِ کل را حساب کن، Order بساز و با pivot quantity به محصولات متصل کن.
  • بعدِ سفارش: سبدِ session خالی شود + پیامِ فلشِ موفقیت.
تستِ گام
به‌عنوانِ مشتری لاگین شو، ۳ محصول اضافه کن، سفارش بده → درِ جدولِ orders ردیف + درِ pivot سه ردیف با quantity درست ثبت شود و سبد خالی شود.

گام ۹: Validation کامل

هدف: هیچ ورودیِ ناخوانده‌ای پذیرفته نشود

جمعِ درسِ ۱۰: همه‌ی فرم‌ها با validation، validated()، @error و old().

کدقواعدِ پیشنهادی
$validated = $request->validate([
    'name'        => ['required', 'string', 'max:255'],
    'description' => ['nullable', 'string'],
    'price'       => ['required', 'integer', 'min:0', 'max:999999999'],
    'category_id' => ['required', 'exists:categories,id'],
    'image'       => ['nullable', 'image', 'mimes:jpg,jpeg,png', 'max:2048'],
]);

// ثبت‌نام:
'email'    => ['required', 'email', 'unique:users,email'],
'password' => ['required', 'string', 'min:8', 'confirmed'],
  • هر فرم = validation + $request->validated() (هرگز $request->all() مستقیم به create).
  • برایِ هر فیلد، @error('name') + old('name') درِ فرم‌هایِ POST.
  • درِ فرمِ ویرایش، unique را با ignore($product->id) تنظیم کن.
  • Mass assignment را با $fillable بسته نگه دار (درسِ ۱۵).
تستِ گام
با پسوردِ ۴ حرفی ثبت‌نام کن → خطا با پیامِ فارسیِ خوش‌خوان نشان داده شود و مقدارِ قبلیِ فیلدها با old() حفظ شود. با یک فایلِ exe فرمِ محصول → خطایِ mimes بگیری.

گام ۱۰: تستِ نهایی و امنیت

هدف: کلِ جریانِ یک خریدِ واقعی بدونِ خلل

جمعِ درسِ ۱۵ + دو سناریویِ کامل از اول تا آخر.

سناریوی مشتری

ثبت‌نام → جستجو → افزودن به سبد → سفارش → دیدنِ پیامِ موفقیت.

سناریوی مدیر

لاگین → ساختِ محصول با عکس → ویرایش → نمایشِ عکس درِ صفحه‌ی عمومیِ سایت.

  • @csrf درِ همه‌ی فرم‌هایِ POST/PUT/DELETE؛ @method('DELETE') درِ فرمِ حذف.
  • اکسکیپ: درِ همه‌ی بلیدها {{ }}؛ هیچ {!! !!}ای رویِ داده‌ی کاربر نباشد.
  • rate limit: throttle:login رویِ POST /login (۵ درِ دقیقه).
  • محیطِ تولید: APP_ENV=production + APP_DEBUG=false درِ .envِ سرور.
  • public فقط only(['index','show'])؛ پنل با auth + check-role:admin.
تستِ نهایی
هر دو سناریو را از اول تا آخر (بدونِ استفاده از Tinker و بدونِ دست‌کاریِ مستقیمِ دیتابیس) اجرا کن — همه‌چیز باید واقعیِ واقعی کار کند. 🎉

🏆 چالش‌هایِ پس از پروژه
  1. یک فیلدِ «تخفیف» به محصول اضافه کن و قیمتِ نهایی را حساب کن.
  2. فیلترِ قیمت درِ فهرست (بالای X تومان / زیر Y تومان) اضافه کن.
  3. صفحه‌ی «سفارش‌هایِ من» برایِ هر مشتری (hasMany orders).
💡 و حالا؟

مباحثِ پیشرفته‌تر (API و Sanctum، صف‌ها، events و notifications، تست‌نویسی) عمداً تویِ این دوره نیامدند — برایِ «مرحله‌ی بعدی» است. با همین فروشگاه، حالا پایه‌ی رفتن به آن‌ها را داری.

🏆 چیزی که از این دوره تویِ ذهنت بماند

  1. یک سایتِ واقعی ترکیبی است از: روت + کنترلر + مدل + بلید — و «ترتیبِ میان‌افزارها» حرفِ آخر را می‌زند.
  2. «داده در دیتابیس، فایل در storage» — فقط مسیرِ فایل را ذخیره کن.
  3. همیشه به ورودیِ کاربر بدباش: validated()، {{ }} و @csrf.
  4. هر صفحه‌ای که middleware نداشته باشد «درِ بدونِ قفل» است؛ از resource فقط همان متدهایی را بساز که لازم داری.
  5. برایِ توسعه، وضعیتِ قابلِ بازتولید (migrate:fresh --seed) مهم‌تر از داده‌ای است که دستی ست کرده‌ای.
  6. پروژه‌ی بعدی‌ات را با همین ساختارِ ساده شروع کن؛ بعد پیچیدگی اضافه کن، نه قبلش.
